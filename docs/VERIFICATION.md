# 最新滚动与表头修复的验证

## 对应修改版

`header-stable-v3` 的 SHA-256：

```text
54dba73f8a943e5bdb55c8d9352ac675d8b599ab15cd2e4f582689c1f4ac75b7
```

验证于 Windows x64 环境完成。最后一轮对比的主窗口、列表和表头 DPI 均为 144；修复前后表头均为 1092 × 37 像素。

源码整理后还使用包内的 `compile-helper.ps1`、`native-smooth-scroll.c` 与 `build_header_stable.py`，在指定 noflash 中间基线上重新构建。输出与以上 SHA-256 完全一致。这证明最新模块的整理副本可以重建该最终阶段，不代表已补齐从官网原版开始的全部构建链。

## 根因与改动

旧滚动逻辑为避免原生滚动把动画画面重复移动，在提交列表位置时短暂关闭整个 ListView 的重绘。实际 Windows 控件路径会影响表头的可见性，因此表头可能闪空。

新逻辑在原生位置提交期间临时限制正文的窗口区域，保留表头与滚动条，不再在成功路径上切换整个列表的重绘状态。原区域在提交后立即恢复；设置区域失败时保留原有回退保护。

## 回归检查

- 明暗模式各 14 个滚动场景，包括连续滚动、方向反转、高精度滚轮、直接滚动条操作、动画中排序及重绘状态中断。
- 滚动后分别对名称、大小、安装时间排序。
- 固定外侧列边界、内部列宽调整及窗口缩放。
- 提交后窗口区域与原状态一致。
- 缓存不透明度、计时器退出与重复操作后的 GDI 资源计数。
- 30 个机器码用例，覆盖正常提交、失败回退、区域对象释放及 subclass 生命周期。

这些检查针对指定输入和输出版本。基础源码快照、其他 Geek 版本及所有 Windows / DPI 组合未由这些结果一并保证。
